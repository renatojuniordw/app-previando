# 06 — AI
> Arquitetura de modelos OpenAI — hierarquia por criticidade

---

## Princípios

1. IA nunca toma decisões jurídicas — apenas estrutura e formata
2. Output sempre requer revisão do advogado — UI não permite usar parecer sem abrir o editor
3. Temperatura 0 para extração, 0.3 para geração de texto
4. Input sempre sanitizado com `sanitizeForAI()` antes do prompt
5. Custo monitorado por geração — tokens e USD logados
6. Modelo centralizado em `src/lib/ai-models.ts` — com exceção conhecida do BPC (ver seção "Desvios")
7. Todo prompt salvo em `opinions.promptUsed` para auditoria
8. Rodapé "Previando" em todo parecer gerado

## Constantes de Modelos

Arquivo: `src/lib/ai-models.ts`

```typescript
const AI_MODELS_MAP = {
  CRITICAL:    'gpt-4.1-mini',  // tarefas jurídicas e extração previdenciária
  OPERATIONAL: 'gpt-4.1-nano',  // tarefas simples de texto (resumos, classificação)
} as const

export const AI_MODELS = AI_MODELS_MAP

// Máximo suportado pelo modelo gpt-4.1-mini
export const AI_MAX_TOKENS: number = 16384

// Custo blended estimado por token (~2:1 ratio input:output)
// gpt-4.1-mini: $0.40/1M input, $1.60/1M output → ~$0.00000080/token
// gpt-4.1-nano: $0.10/1M input, $0.40/1M output → ~$0.00000020/token
export const AI_COST_PER_TOKEN: Record<string, number> = {
  'gpt-4.1-mini': 0.0000008,
  'gpt-4.1-nano':  0.0000002,
}
```

### Hierarquia

| Nível | Constante | Modelo | Quando usar |
|---|---|---|---|
| CRITICAL | `AI_MODELS.CRITICAL` | `gpt-4.1-mini` | Extração CNIS, pareceres jurídicos, diagnóstico de prontuário |
| OPERATIONAL | `AI_MODELS.OPERATIONAL` | `gpt-4.1-nano` | Validação CNIS, tarefas simples de texto |

**Por que gpt-4.1-mini para tarefas críticas?**
O CNIS é traiçoeiro: vínculos quebrados, múltiplos NITs, contribuições extemporâneas, períodos concomitantes. Um modelo menos capaz tende a simplificar demais ou dropar detalhes — o que vira cálculo errado e perda de confiança do advogado. Confiança é o ativo principal do Previando.

## Cliente OpenAI

Arquivo: `src/lib/openai.ts`

O cliente OpenAI é um singleton com inicialização preguiçosa (lazy), acessado via `getOpenAI()`. Também expõe um proxy `openai` para importação direta.

```typescript
import OpenAI from 'openai'

let _openai: OpenAI | null = null

export function getOpenAI(): OpenAI {
  if (!_openai) {
    _openai = new OpenAI({
      apiKey: process.env.OPENAI_API_KEY ?? 'placeholder',
      timeout: 180_000,  // 3 minutos para extrações grandes (CNIS 20+ páginas)
      maxRetries: 3,
    })
  }
  return _openai
}

// Proxy para compatibilidade com importação direta
export const openai = new Proxy({} as OpenAI, {
  get(_target, prop) {
    return (getOpenAI() as never)[prop as keyof OpenAI]
  },
})
```

### Configuração

| Parâmetro | Valor | Justificativa |
|---|---|---|
| `timeout` | 180 000ms (3 min) | CNIS de 20+ páginas pode demorar |
| `maxRetries` | 3 | Tolerância a falhas transitórias |
| `apiKey` | `process.env.OPENAI_API_KEY` | Variável de ambiente obrigatória |

## Sanitização de Input

Arquivo: `src/lib/sanitize.ts`

A função `sanitizeForAI()` protege contra injeção de prompts e normaliza texto antes de enviá-lo ao modelo.

```typescript
export function sanitizeForAI(input: string, maxLength: number = 3000): string {
  return input
    .replace(/---/g, '')
    .replace(/```/g, '')
    .replace(/ignore (previous|all) instructions/gi, '')
    .replace(/you are now|act as|pretend (you are|to be)|jailbreak/gi, '')
    .replace(/[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]/g, ' ')
    .slice(0, maxLength)
    .trim()
}
```

### Comportamento

| Operação | Detalhe |
|---|---|
| Remove markdown fences | `---` e `` ``` `` são removidos |
| Anti-prompt injection | Padrões como "ignore all instructions", "act as", "jailbreak" são removidos |
| Remove caracteres de controle | `\x00-\x08`, `\x0B`, `\x0C`, `\x0E-\x1F`, `\x7F` são substituídos por espaço |
| Preserva tabs e newlines | `\t` e `\n` são mantidos intencionalmente |
| Trunca input | `maxLength` (padrão 3000) limita o tamanho |

### Uso no BPC

O serviço BPC usa uma função auxiliar `s()` que é um wrapper conciso:

```typescript
function s(input: string | undefined, maxLen: number = 3000): string {
  return sanitizeForAI(input ?? '', maxLen)
}
```

## Desvios Conhecidos

### `gpt-4o-mini` hardcoded no BPC

O serviço BPC (`src/services/bpc/index.ts`) usa `gpt-4o-mini` diretamente hardcoded em cada função, em vez de usar as constantes `AI_MODELS.*`. Isso viola a regra "modelo nunca hardcoded".

**Justificativa:** O BPC é um módulo experimental com prompts especializados e volumes baixos. O modelo `gpt-4o-mini` foi escolhido por custo/benefício para tarefas de texto livre (relatos, perguntas, carrossel).

**Risco:** Se o modelo for descontinuado ou substituído, todas as 6 funções do BPC precisam ser atualizadas manualmente.

**TODO:** Criar `AI_MODELS.BPC` ou `AI_MODELS.LIGHTWEIGHT` e migrar o BPC para usar a constante.

## Detalhamento das Operações

### CNIS Full Parse

Arquivo: `src/services/cnis/ai-parser.ts` — função `parseCnisWithAI()`

- **Modelo:** `AI_MODELS.CRITICAL` (gpt-4.1-mini)
- **Temperature:** 0 (extração determinística)
- **Max Tokens:** `AI_MAX_TOKENS` (16384)
- **Timeout:** 180 000ms (passado explicitamente na chamada)
- **Input sanitizado:** `sanitizeForAI(pdfText, 120000)` — limite generoso para CNIS completo
- **System prompt:** Especialista em Direito Previdenciário, extrai dados estruturados do CNIS
- **Output:** JSON com NIT, nome, data de nascimento, períodos, salários, gaps
- **Fallback:** Se o JSON falhar, tenta extrair com regex `/\{[\s\S]*\}/`
- **Log:** `model`, `tokens`, `finish_reason` logados via Logger

### CNIS Validation (Two-Pass)

Arquivo: `src/services/cnis/ai-parser.ts` — função `validateCnisProgrammaticResult()`

- **Modelo:** `AI_MODELS.OPERATIONAL` (gpt-4.1-nano)
- **Temperature:** 0
- **Max Tokens:** 100
- **Input:** head (8000 chars) + tail (3000 chars) do texto do CNIS
- **Objetivo:** Validar que NIT, nome, primeira e última contribuição batem com o texto
- **Output:** `{"valid": true}` ou `{"valid": false, "reason": "..."}`
- **Estratégia two-pass:** Parser programático primeiro; se falhar ou for ambíguo, AI valida

### Geração de Parecer

Arquivo: `src/services/opinion-generator.ts` — função `generateOpinion()`

- **Modelo:** `AI_MODELS.CRITICAL` (gpt-4.1-mini)
- **Temperature:** 0.3
- **Max Tokens:** `AI_MAX_TOKENS` (16384)
- **Input sanitizado:** `sanitizeForAI()` aplicado a clientName, notas e resumo do CNIS
- **System prompt:** Assistente de direito previdenciário, regras absolutas de segurança
- **Regras do system prompt:**
  1. Usar APENAS os dados fornecidos — nunca inventar
  2. Não fazer afirmações categóricas sobre aprovação pelo INSS
  3. Sempre incluir aviso de parecer preliminar
  4. Máximo 4 parágrafos
  5. Nunca citar leis sem certeza absoluta
  6. Rodapé: "Calculado via Previando (app.previando.com.br)"
- **Output:** `OpinionOutput` com `content`, `promptUsed`, `tokensUsed`, `costUsd`, `model`
- **Custo calculado:** `tokensUsed * AI_COST_PER_TOKEN[model]`

### Diagnóstico de Prontuário

Arquivo: `src/app/api/cases/[id]/notes/diagnosis/route.ts`

- **Modelo:** `AI_MODELS.CRITICAL` (gpt-4.1-mini)
- **Max Tokens:** `AI_MAX_TOKENS` (16384)
- **Rate limit:** 10 diagnósticos/hora por usuário

### Operações BPC

Arquivo: `src/services/bpc/index.ts`

Todas as funções BPC seguem o mesmo padrão:
1. Sanitizam inputs com `sanitizeForAI()` via wrapper `s()`
2. Constroem prompts com funções dedicadas em `@/lib/prompts/bpc/`
3. Chamam `getOpenAI().chat.completions.create()` com `gpt-4o-mini`
4. Retornam o conteúdo da resposta

Cada operação tem limites de tokens específicos:
- Pre-Análise, Laudo, Perguntas Sociais, Perguntas Médicas: 3000 tokens
- Checklist: 1500 tokens
- Carrossel: 2000 tokens (temperature 0.5 para criatividade)

## Rate Limiting

Arquivo: `src/lib/rate-limit.ts`

Rate limiting via Redis com sliding window, com fallback em memória local quando Redis está indisponível.

```typescript
export async function rateLimit(
  key: string,
  limit: number,
  windowSeconds: number
): Promise<RateLimitResult>
```

### Limites por Operação

| Operação | Limite | Janela | Redis Key |
|---|---|---|---|
| Pareceres | 20/hora | 3600s | `ai:{userId}` |
| Diagnósticos | 10/hora | 3600s | `diagnosis:{userId}` |
| BPC (todas as operações) | 15/hora | 3600s | `bpc:{userId}` |
| BPC Carrossel (social media) | 15/hora | 3600s | `bpc-social:{userId}` |

### Fallback

Quando Redis está indisponível, o rate limiter usa um `Map<string, {count, reset}>` em memória com limpeza a cada 60 segundos.

## Regras Globais

1. **Temperatura:** 0 para extração (CNIS), 0.3 para texto (pareceres, BPC), 0.5 para criatividade (carrossel)
2. **Max tokens:** Sempre definido — nunca aberto. Constante `AI_MAX_TOKENS` (16384) para operações críticas.
3. **Timeout:** 180s — cobre CNIS de 20+ páginas
4. **Retries:** 3 tentativas automáticas no cliente OpenAI
5. **Sanitização:** Todo input passa por `sanitizeForAI()` antes do prompt
6. **Auditoria:** Todo prompt salvo em `opinions.promptUsed`
7. **Custo:** Todo custo salvo em `opinions.generationCostUsd` e `opinions.tokensUsed`
8. **Revisão obrigatória:** Advogado sempre revisa — UI não permite usar parecer sem abrir o editor
9. **Rodapé:** "Calculado via Previando (app.previando.com.br)" em todo parecer gerado
10. **Modelo centralizado:** Via `AI_MODELS.*` — exceção conhecida: BPC usa `gpt-4o-mini` hardcoded
